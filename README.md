# dax-with-js

**Power BI reports rendered in JavaScript, hosted on a CDN, driven by a DAX measure.**

A DAX measure returns data. A JavaScript file on jsDelivr does the layout, the
maths and the interaction. The HTML Content visual is the bridge between them.

This repo is the working proof behind the blog post *"Power BI reporting with
DAX and JavaScript"*. Everything here is synthetic: TrailPeak Outfitters is a
fictional outdoor retailer, and every number is generated by a seeded script.

## The idea in one diagram

```
DAX measure                    CDN JavaScript              HTML Content visual
-----------                    --------------              -------------------
returns DATA        ------>    layout                ---->  renders it
  facts at grain               geometry                     (standard edition)
  no markup                    ranking, cumulative
  no colours                   number formatting
  no formatting                colour, interaction
```

The split matters. Most DAX-generates-HTML examples put everything in the
measure: markup, inline styles, hex colours, `FORMAT()` calls, even SVG
coordinate arithmetic. That works, and it does not scale. Move the presentation
into a JavaScript file and the measure collapses to a serialiser.

## Quick start

**1. Install the right visual.** [HTML Content](https://appsource.microsoft.com/en-us/product/power-bi-visuals/WA200001930)
from AppSource, the **standard** edition.

> The certified **HTML Content (lite)** edition will not work. It sanitizes the
> markup and strips `<script>` tags, so the visual renders blank with no error
> message. The two GUIDs differ by one character: lite ends `...D3A6865`,
> standard ends `...D3A6855`. Check this first if you see a blank box.

**2. Add a measure** that returns a container, your data, and a script tag:

```dax
My Visual =
VAR CdnUrl = "https://cdn.jsdelivr.net/gh/USER/REPO@v1.0.0/path/to/file.js"
VAR Payload =
    "window.__myData={rows:[" & <your CONCATENATEX here> & "]};"
RETURN
    "<div id='my-root'></div>"
        & "<script>" & Payload
        & "if(window.MYVIZ&&window.MYVIZ.render){window.MYVIZ.render();}"
        & "</script>"
        & "<script src='" & CdnUrl & "'></script>"
```

**3. Host the JavaScript** on jsDelivr, pinned to a tag:

```
https://cdn.jsdelivr.net/gh/{user}/{repo}@{tag-or-sha}/file.js
```

**4. Drop the measure** on the visual's Values well.

## Hosting rules

- **Use** `cdn.jsdelivr.net/gh/...` pinned to a **tag or commit SHA**. Branch
  paths cache for around 12 hours and will have you debugging stale code.
- **Never** `raw.githubusercontent.com`. It serves `text/plain` with
  `X-Content-Type-Options: nosniff`, so the browser refuses to execute it.
- **Never** Google Drive. HTML wrapper, redirects, wrong content type.
- The repo must be **public**. A private repo returns 404 from every CDN, and
  jsDelivr caches that failure for a while even after you flip it back.
- `cdn.statically.io` is a usable alternative with the same guarantees if
  jsDelivr's version index is being stubborn.

Verify before touching Power BI. Both of these must be right:

```bash
curl -sI "https://cdn.jsdelivr.net/gh/USER/REPO@v1.0.0/file.js" \
  | grep -iE "content-type|access-control-allow-origin"
# content-type: application/javascript; charset=utf-8
# access-control-allow-origin: *
```

## The sandbox you are coding against

Custom visuals run in an iframe sandboxed `allow-scripts` and, critically,
**without** `allow-same-origin`. The document has a null origin.

| Constraint | Consequence |
|---|---|
| Null origin | No cookies, no `localStorage`, no `sessionStorage`. State goes on a `window` global. |
| External fetch | Only works if the host sends `Access-Control-Allow-Origin: *` and a real JS MIME type. |
| DOM is replaced | The visual rewrites its DOM and re-inserts the script tags on **every** cross-filter, resize and refresh. Your code runs many times per session. |
| Load order | Not guaranteed. The inline data script may run before **or** after the CDN file. Handle both. |
| One way | Nothing is written back to the model. This visual cannot cross-filter others. |
| Uncertified | No PDF or PowerPoint export from the standard edition. |

### Idempotency is the whole game

Almost every *"the visual needs a page refresh to redraw"* report traces back to
a script that assumed it would run once. Both files here handle it:

- An **install guard** at the top. On re-execution it calls the already-installed
  `boot()` and returns rather than rebuilding the closure.
- Styles injected only if absent from the current document.
- Listeners **delegated onto the root**, and wired once per root element. Wiring
  per render stacks handlers, and two handlers means a toggle fires twice and
  nets to no change.
- Renders coalesced through `requestAnimationFrame`, so the inline script's
  `render()` call and the file's own re-boot produce one paint.
- UI state on `window.__*State`, restored after each render.

`preview-page.html` reproduces the re-injection exactly. **"Simulate
cross-filter" is the test that matters.**

## Two things that will bite you

### Locale will corrupt your payload

`FORMAT()` emits locale-dependent separators. On a de-DE or fr-FR workspace
`1234.56` becomes `"1234,56"` and the payload silently stops being valid
JavaScript. So money crosses as **integer minor units** and ratios as **integer
basis points**, both via `FORMAT(x, "0")`, which emits no separator in any
locale. The browser divides them back.

### Text needs escaping, in this order

The payload is JavaScript, not JSON, so single-quoted strings and bare keys are
legal, which keeps the DAX free of `""` soup. Text values still need:

1. backslash to two backslashes
2. `'` to backslash + `'`
3. CR to space
4. LF to space
5. `<` to backslash + `u003C`

Step 1 must come first or the backslash added in step 2 gets doubled. Step 5
matters because a value containing a closing script tag would end the block
early and dump the rest of the payload on screen. A product called `O'Brien's`
makes step 2 non-theoretical.

Build the backslash with `UNICHAR(92)`. A bare `"\"` in DAX reads like a typo
and does not survive copy-paste through JSON-based tooling.

## The measure ceiling

A DAX measure holds roughly **2,100,000 characters**. Columns silently truncate
at 32,766, which is a different and much lower limit.

The one-page build ships ~1.37M characters (~65% of the ceiling): 7,200 P&L
facts and 40,237 sales facts. That budget is why keys are emitted as bare
integers and facts as flat fixed-stride arrays. Arrays of objects would roughly
triple it. Quoting the keys as strings alone cost 190K characters.

## The honest limitation

**A JavaScript visual can receive filter context. It cannot emit it.**

Cross-filtering *out* of a visual requires that visual's own compiled TypeScript
to build selection identities and call `selectionManager.select()`. HTML Content
never does; its source has no `ISelectionId` reference anywhere. No amount of
injected JavaScript changes that, because the injected code has no handle on
`IVisualHost`.

|  | into the visual | out of the visual |
|---|---|---|
| Filter context (slicers, page filters) | **works** | not possible |
| Selection / cross-highlight | n/a | not possible |
| Export data | returns markup, not rows | not possible |

There are two honest answers:

1. **Make the page the visual.** If the whole page is one visual, there is
   nothing to cross-filter *to*. Ship facts, filter in the browser. That is what
   `trailpeak-page.js` does, and every click is sub-millisecond.
2. **Use [Deneb](https://deneb.guide/)** when clicking the chart itself must
   drive other visuals. It binds real model fields, implements selection, and
   stays certified. The cost is Vega-Lite grammar plus extra measures whose only
   job is pre-formatting text and colours.

Certification requires no external loading, so this technique is fundamentally
incompatible with a certified visual. That is the real trade, more than export.

## Local development

```bash
start trailpeak/preview-page.html      # Windows
open  trailpeak/preview-page.html      # macOS
```

No build step, no server. The harness reproduces the visual's script
re-injection and reports whether the render stayed idempotent.

### Releasing

```bash
git commit -am "..."
git tag v1.0.1 && git push origin master v1.0.1
```

Then bump the `CdnUrl` var in the measure. Tags are immutable on jsDelivr, so an
old report keeps working against the old tag. That is the point of pinning.
